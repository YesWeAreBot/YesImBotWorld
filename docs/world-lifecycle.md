# 暂停、重置与创世

所有 Koishi 指令、WebUI 管理指令和旧 HTTP 入口共用 `WorldService` 的生命周期队列。
启动和普通创世不会并发执行；暂停、重置、强制创世和回档会先取消当前推理，再等待旧生命周期退出。
模型不响应取消时，迟到结果也不能继续发起下一阶段请求、写入新世界或向新角色投递。

停止分为两步：关闭新任务入口、取消推理；随后等待已经开始的本地写入完成。
排空范围包括世界日志打开与恢复、元数据、分段记忆整理、成长账本、记事本写入、时钟保存和历史消息补拉。
访客连接在停机时按程序登记离场，不再要求已停止的模型叙述离场。
页面读取世界状态也遵循文件操作屏障，不能在重置中途恢复旧日志镜像。

`genesis-pending.json` 表示创世流程尚未完成。`prepared` 表示清空聊天记录和重置时钟已完成；
此后的重试不会再次清空聊天或重置时间。世界状态已提交但手机或角色上下文尚未保存时，仍不允许启动。
普通 `world.init` 可以完成该次创世；`world.init -f` 则归档并重新生成。
完整保存初始角色上下文后才移除标记。标记随存档保存、恢复，重置时删除。

World 裁定的每次生成最多修正三轮协议/事实边界问题。连续调用可能是同一次创世的修正尝试，
不能只凭调用频率判定旧心跳仍在运行。设备校验反馈会标明字段和违规片段：手机摆放、外壳等物理描述可以裁定，
亮屏、暗屏、锁屏、界面和聊天内容须由设备工具确认；创世也不能自行假定这些状态。

离线回归通过受控 Promise 暂停模型、磁盘写入、访客离场和平台补拉，在该位置执行停止/重置/重新创世，
验证旧结果不能覆盖新数据、任务不会自行恢复、创世重试保留已提交的时间与状态。
