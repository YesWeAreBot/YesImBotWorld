# 模型 API、工具调用与提示词

[文档目录](README.md) · [项目首页](../README.md)

各模型的 API 配置、输出协议、工具声明及提示词更新规则。

## Bot-LLM 调用协议

模型配置中的 `apiType` 选择请求 API，默认 `chat-completions`，旧配置无需迁移。Bot、World、成长整理、图片/音视频解释器和手机助手都可分别选择：

| 配置值 | API | 地址示例 |
| --- | --- | --- |
| `chat-completions` | OpenAI Chat Completions | `https://api.openai.com/v1` |
| `responses` | OpenAI Responses | `https://api.openai.com/v1/responses` |
| `anthropic` | Anthropic Messages | `https://api.anthropic.com` |

地址可填根域、`/v1` 或完整生成端点；根域自动补 `/v1`，已有代理路径保留，不重复拼接。协议必须匹配服务提供的接口，模型名称不决定协议。WebUI 可在原有配置页选择协议和获取模型列表，使用未保存的地址、协议与密钥草稿；Anthropic 列表使用其专用认证头，最多读取五页，未列出的模型仍可直接填写名称。

成长整理选择“沿用”时继承 Bot 的协议和密钥，手机助手借用时继承 World；独立模式使用各自设置，空密钥不借用主模型密钥。相机的构图说明继承 World 协议，实际生图仍走独立的 OpenAI 兼容 `/images/generations`。音频解释器的 `api=transcription` 仍是独立 `/audio/transcriptions` 转写接口，`apiType` 只影响 `api=chat` 的多模态对话方式。

三种协议都支持保持原位置的文字与图片混排，仍须选择具备视觉能力的模型。目前 Responses / Anthropic 适配器不支持原生音频、视频；遇到这些媒体会明确报告能力不支持，并由 Bot 已有的媒体降级流程尝试配置的解释器，不会把文件静默丢掉或假装听到。音频可选择独立语音转写，原生音视频解释器需使用实际支持 `input_audio` / `video_url` 的 Chat Completions 服务。

温度仅在 Chat Completions 请求中发送；Responses 和 Anthropic 使用服务默认值，避免向不支持自定义温度的推理模型传入默认参数。`world.responseFormat` / `bot.growth.responseFormat` 仍控制返回形式，独立于 API 选择；Anthropic 不支持 `json_object`，应选择 `json_schema`（服务及模型须支持）或相应文本/工具模式，失败不会自动降级到另一协议。

结构化输出会按所选服务支持的 Schema 子集整理传输声明，收到后仍经过项目完整业务校验；这不意味着任意 JSON Schema 或任意模型均支持结构化输出。配置 `disableThinking` 时，Chat Completions 使用兼容后端的思考开关，Responses 使用 `reasoning.effort=none`，Anthropic 使用 `thinking.type=disabled`；不支持这些控制的模型应保持关闭本选项。

`bot.nativeToolCalls` 选择工具的输出方式：

- 开启：第一次生成时冻结当时可用工具的原生 function calling 声明，直到下一次成功压缩才更新。每次请求恰好一个调用；应用原始 JSON Schema 保留嵌套结构、枚举与必填字段。期间新增工具或更新参数时，若固定声明尚未包含它们，可在正文输出一个完整 `{"name":"工具名","arguments":{},"duration":0}` 对象。
- 关闭：在正文输出一个 `{"name":"工具名","arguments":{},"duration":0}` 对象。应用展开事件附带原始参数 schema；不要求调用不存在的原生工具接口。

工具新增、失效及参数变更以事件追加，实际允许集立即更新；关闭应用会收起其即时操作能力，但不抹去已经学会的工具用法。旧原生声明也不代表当前执行权限。生成后的调用还会在派发和实际执行前复核，避免使用过期界面。没有关注的设备变化不会仅因后台工具刷新而泄露，需等到实际可感知时才更新 Bot 所知的能力。

能力通知在下一轮生成前汇总净变化，不记录瞬时排队造成的 `cancel` 开关。同一上下文窗口内，相同用法的工具恢复只通知名称，首次出现或用法变化呈现精简用途与参数约束；完整说明通过 `help(tool)` 按需读取，调用失败时补充相关用法，同一窗口不反复展开相同说明。重启复用已交付声明，成功压缩后从新的固定工具块开始。

对已经知道的聊天、手机应用和电脑操作，程序可补齐真实的拿起手机、打开应用、选择频道或打开电脑步骤，再执行所选工具。`send` 每次必须明确填写目标频道 `id`，即使已打开目标频道也不能省略；缺少目标时不执行前置导航，也不默认发送到当前频道。其他允许省略频道的工具只能使用当前已打开的频道。权限不足、工具禁用或归属歧义、手机不可达或损坏时拒绝，不猜目标、不探测未知应用。每一步按原权限与调度执行，保存真实回执，以 `navigationFor` 关联目标工具；前置步骤失败即停止，不追加假成功，也不增加 LLM 决策轮次。重新打开后仍校验工具实际存在。工具目录是角色知识，不改写已发送的固定声明和历史前缀。

工具反馈直接呈现读到的内容、当前界面或剧情，即时操作不再另发“已受理”。只有下一轮生成时仍未结束的自主操作，才追加一次简短进度；发送、保存等保留必要的完成确认，失败、部分成功、未知结果和警告照常交付。`think` 的想法已经在调用记录中，其成功确认不再进入模型请求。如果因此缺少接续下一轮生成的输入，会持久追加一句“请选择下一步。”作为对话轮次边界；它不代表成功，也不进入成长证据或压缩记忆。程序明确提供的精简呈现仅在新事件首次保存时冻结，原始回执、成长证据与恢复记录保留；不会依据“成功”等关键词过滤聊天或任意工具正文，也不会改写旧请求。

自主设备即时操作先交付真实结果，再生成下一步；拿放手机、切换应用不再按 `duration` 推迟已完成的回执。发送的打字耗时保留：尚未到发送时刻时可以取消；手机失效会取消尚未提交的手机操作，恢复后不会复活旧发送，已经提交的发送仍交付真实回执。人工操作的回执时序及 World 动作的专注配置保留，等待设备回执不会锁住人工接管。发完消息可以继续留在会话；主动放下仍关闭应用、清除当前频道，通知策略不变。再次拿起在桌面，后续明确的设备操作可以经上述真实导航重新进入目标界面。

系统提示与格式错误反馈随该开关选择。原生响应中出现多个调用会整体拒绝，不静默挑第一个执行；非法参数 JSON 也不再降级为空参数。

两种协议共用耗时解析：`duration` 可以位于正文 JSON 顶层或工具 `arguments` 中，统一提取为调度耗时；两处同时提供时必须相等。负数、非有限值、空字符串等无效值明确拒绝，不静默当作零耗时。采纳行动建议时同样调用真实工具，例如 `{"name":"act","arguments":{"description":"沿着小路去河边"},"duration":120}`；只输出裸序号不属于工具调用协议。

### 内置提示词与覆盖

WebUI 展示运行时使用的模板。自然语言 World 裁定及内部应用任务使用 `narrativeSystem`，只读感知整理使用 `presentationSystem`；创世辅助判定与 Bot 记忆压缩模板保持独立。入场、离开、行动（含主动观察）、内部观察与自然演化走同一套世界裁定语义，不建立跨任务的 World 对话历史。

旧结构裁定 `adjudicationSystem`、旧 `system`、`send_event` / Markdown 更新及访客叙事模板已停用，不会迁入新的 `narrativeSystem` 裁定提示。读取配置不改写原文件；首次保存时，含停用模板的原始覆盖备份到 `webui/prompts.legacy.json`。有效的用户覆盖保留，需在编辑器中「恢复默认」才采用更新后的内置文本。旧 `adjudicationSystem` 覆盖会按停用模板隔离，避免继续要求 `propose_world` 或实体操作；需要沿用的叙事风格应按新协议加入 `narrativeSystem`。World 模板保存后用于后续请求；Bot 的固定提示块在下一次成功压缩时刷新，已发送的请求与历史前缀不改写。

内置提示区分受理、提交与完成；`duration` 不承诺可撤销，`cancel` 不能回滚既有副作用。设备界面变化不自动等于角色移动或某人接管，同账号消息不自动成为 Bot 自主经历。虚构天气、网页和文件查询只呈现已知观测；命令与写文件走明确动作裁定，不能假称执行了真实操作系统命令。`rest` 是可打断计时，不宣称已恢复体力；记忆压缩也不改变身体状态。

聊天修正规则在恢复运行时作为新事件追加，固定提示块仍在正常压缩后更新，旧请求和作者原文不改写。角色与世界提示不再用实现层的控制类型定义人物身份；内部投递编号仍保留。历史记录明确区分昵称与正文、回读快照与新发言；平台表情包标记随每次消息保存，并传到原生图像与文字摘要旁。重复读取同一媒体可引用当前窗口已展开的原图，旧事件保持原有呈现方式。
