# 世界心跳与角色行动边界

`evolve` 是外部世界的演化，不是受控角色的下一回合。它可以让 NPC 继续工作、让天气变化，也可以发展角色尚不知道的远处事件。`worldState` 保存当前仍需承接的世界工作记忆；实际经过和来源随事务日志追加，旧记录不重写。

角色不会因为一次心跳、等候结束、压缩或离线时间过去，就被世界续写成困倦、入睡、醒来或主动做了什么。已受理的 `pendingActions` 只由其 `action` 开始/结束裁定推进和结算。睡觉是角色自己提出的身体行动；如果它已成为持续动作，也保留真实开始和预计结算边界，世界仍可在期间活动。

意识状态通过可选的 `consciousness` 明确记录，旧数据缺省保持未知。一个有限例外是：已经确立 `asleep`、且没有待结算睡眠动作时，世界心跳或离线演化可以依据实际流逝的时间裁定自然睡醒，通过 `externalChanges` 和引用它的 `actorEffects` 同笔更新为 `awake`，不代写醒后的选择。`unconscious` 的恢复需要已确立的恢复条件或真实外因，不能任意计时唤醒。明确睡眠、昏迷期间暂停自主生成和屏幕阅读，已提交动作仍会结算；通知不直接把角色判定为清醒。

## 写入权限

心跳的输出契约不包含 `actorStates` 和 `outcome`，运行时也拒绝这两个字段。它通过以下来源关系表达实际外部影响：

- `externalChanges`：本轮新发生的外部经过，每项只有本次提案内的 `id` 和自然语言 `description`。
- `actorEffects`：仅在实际外部原因改变角色身体或处境时填写，提供 `actorId`、引用原因的 `changeIds` 和客观状态全文。例如雨水打湿衣服、他人撞到身体；不决定角色接下来避雨、回话或如何理解这件事。
- `perceptions[].changeIds`：每份被动感知必须引用本轮外部变化，且仅包含接收者按位置、注意和感官实际获得的部分。原因完整记录可以全知，交付内容不能全知。远处发生事情无需发送感知，也无需让角色醒来。
- `phoneChangeIds`：心跳改变手机物理条件时同样需要本轮外部原因；不能通过这条通道执行软件、生成通知或杜撰真实聊天。

持续状态确实变化时更新世界记忆，同时登记本轮外部原因。任务提供 `worldDocument` 时优先提交 `worldPatch`，也保留 `worldState` 全文回退；二者不能同时填写。事件也可以不改变持续状态：例如已有风的院子里又吹过一阵风，角色感到了它，但位置、物品和正在进行的事情都没有改变。此时省略状态字段即可；程序保留原状态，仍将 `externalChanges` 和实际感知写入同一事务。没有角色感知到的远处事件同样可以只记录来源经过，不必制造接收者。

没有外部变化时返回 `perceptions:[]` 即可。省略 `worldState`、原样返回存档状态或原样返回本轮提供的投影状态，都视为 `quiet`，不写入空事务，不把投影清理覆盖回存档。输入投影可能归并空行、隐藏旧设备断言或隔离旧的当前日期；这些处理不是新发生的物理事件。没有外部原因却真正改写状态，仍会被拒绝，不能用“只是换个措辞”绕过来源校验。

每份感知和身体影响都必须引用至少一个本轮定义的原因；缺失、空数组、重复引用、未定义原因、重复原因编号和重复接收者会给出包含字段位置的错误。`phoneState` 与 `phoneChangeIds` 必须成对提交；手机物理条件无变化时一起省略。普通喝水、休息、收拾与探索都可以成为符合实际处境的建议，无需每轮制造冲突、选择或新人物。

程序校验原因引用、身份、事务版本、设备事实与时钟边界，将来源元数据和状态/感知一起保存。新日志中的 `commit.evolution` 记录原因及每份身体影响、感知的对应关系，便于追溯；它不会作为全知说明交给角色。新提交的 `source=evolve` 必须带这份来源，不能借兼容路径绕过。历史日志没有这一字段仍按原格式加载，不将旧记录误认证成符合新约束的裁定。

心跳输入不再附带上一轮角色感知，而是提供持久处境与最近行动的终态；已取消、失败或完成的行动不授权继续行动。手机位置的读取投影以程序持有状态为准，隔离明确矛盾的旧位置子句，不改存档。提交前还检查明确的持有矛盾、心跳代替受控角色决定或继续主动行动，以及把未变化背景充当新事件的表达；失败沿用原有有限纠正流程。NPC 行动和实际外因造成的身体影响仍然允许。

这些结构保证权限入口和来源对应关系，不能证明任意自然语言中的因果判断一定正确。具体因果、空间和注意条件仍由 World 裁定；固定的演化规则随每次请求提供，即使用户覆盖 World 文风提示也不会消失。这里没有用睡眠或情绪词黑名单拒绝合理的外界感知。

## 输出适配与纠正

默认使用 `response_format: json_schema` 直接返回完整单个参数对象。`world.responseFormat=json_object` 可使用 JSON 对象兼容模式；只有显式设为 `tool` 才要求原生 `resolve_world` 工具调用。传输解码器仍兼容仅包含 `name:"resolve_world"` 与 `arguments` 的旧调用封装，`arguments` 可以是对象或完整 JSON 对象字符串。适配仅处理传输形式，不放宽角色权限、来源引用、设备事实、时间、身份及事务校验。

不拼接多个对象，不从说明文字或代码围栏中截取片段，也不修补截断 JSON。若已返回原生工具调用，它必须是唯一且完整的 `resolve_world`；不能在该调用损坏时改取正文里的另一份提案。

校验失败后的纠正请求保留一个稳定的世界任务输入，只追加错误、失败位置及“尚未提交”的说明。无效或不完整的 `assistant.tool_calls` 不会作为合法历史再次发送，错误提案也不作为已发生的世界事实；不重复附加整份世界状态。若纠正请求提供可修复草稿并开放 `repair`，模型可只替换错误顶层字段，例如 `{"repair":{"set":{"outcome":{"status":"completed"}}}}`，或用 `remove` 删除错误字段。`set` 是整字段替换：更新 `perceptions` 须给完整数组，更新 `outcome` 须给完整对象，不作递归合并；`remove` 只删除草稿字段，不删除已保存的世界事实。不能把 `repair` 与完整提案混在同一对象中，不能借修复更换任务、取得权限或绕过校验。

完整提案仍是兼容回退；没有可用草稿或工具未声明 `repair` 时须提交完整提案。修复得到的整份候选重新通过相同的身份、时间、来源、设备和事务检查，只有全部验证及写入成功后才交付感知。网络、存储和取消错误不冒充模型提案错误。

工具声明按任务给出实际可写字段：`action` 和 `app_action` 要求 `outcome`；没有角色原话就不声明 `speechSpoken`，有原话的开始阶段必须明确布尔值。到期结算不再让模型重复生成这一固定字段：未提供时由程序补 `false`，兼容显式 `false`，显式 `true` 仍拒绝，不能静默改写为没说过；只有允许持续开始裁定时才声明 `ongoing`。应用读取只有私有 `perceptions`，应用读写均不声明身体状态、状态栏和行动建议；无手机物理权限时不声明 `phoneState` 及 `phoneChangeIds`。工具声明用于减少无效生成，运行时验证仍是权限边界。

## 按任务提供提示

`buildWorldTaskPrompt` 将系统提示分成稳定公共前缀与本次任务块。前缀保留共同的事实与时间边界、叙述要求、完整世界定义和角色定义；后面只拼接当前 `initialize`、`action`、`observe`、`evolve`、`arrive`、`leave`、`app_observe` 或 `app_action` 的规则。普通行动不再携带创世字段、心跳来源协议或虚构应用读写教程；开始与到期结算分别说明可完成的内容。工具描述也按同一任务收窄，避免删掉字段后仍在别的字段说明里教模型填写它。

默认 `narrativeSystem` 仅保留共同的自然语言文风与连续性要求。已保存的自定义提示逐字保留，不自动删除用户编辑的段落；因此用户自行保留的旧长模板也会继续存在，可在提示词设置中自行精简。自定义文风不会移除程序独立提供的时间、设备事实及任务权限。程序不随机更换提示，不在稳定公共前缀填当前时间，也不反复把固定规则放入任务 JSON。

动态输入只承载状态与任务资料，短字段由固定规则解释：`stateAheadOfClock=true` 不授权把程序时钟推到未来；`retainedDeviceRecords=true` 表示隐藏的旧文件尾部由程序原样接回，不能猜补；`phoneAuthority.stateKnown=false` 表示沿用输入默认物理条件，不表示本次剧情已经确立它们。`phoneState` 和 `phoneHeld` 的权属由 `phoneAuthority.actorId` 指定，不借访客或其他角色的手机状态更新它。`recentEvolution` 是已提交经过的有限窗口，不能重复发生，也不能借其中旧编号作为本轮原因。

`pendingActions` 只列出本次行动以外的待结算行动，`accepted` 只证明已受理，`ongoing` 只证明已有开始裁定，均不能证明已完成。这条约束覆盖所有物理任务，包括另一角色的行动、到访和离场，避免并行角色顺带推进或结算彼此的动作。提出睡觉仍是尝试，能否入睡取决于历法、角色习惯、真实经过与身体状态。

感知保留明确的 `actorId` 路由，即使本轮只有一个角色也不猜地址。`situation` 和 `opportunities` 均不是必填；无变化状态省略，不要求把同一段剧情重述成状态栏，也不要求每次凑建议。纠正请求才开放需要的草稿修复协议，首轮不携带完整的修复教程。

## 世界工作记忆

`worldState` 用于下一轮裁定，需要保留仍有效的事实、秘密、NPC 目标、未完成过程、交谈进度和约定。已经结束且不再影响后续的细节留在事件日志，工作记忆中可以归纳其后果，不必继续追加完整流水账。历史事件不能因为整理而变成没发生过。

请求附带最多三笔、总计最多6000字符的完整近期外部事件；超出预算的记录仍保存在日志，不截断事件正文。这是有限承接窗口，不是全部历史。`evolutionSinceTU` 与 `elapsedEvolutionWorldSeconds` 从最近已提交演化或状态变更承接，独立于状态正文的更新时间，避免同文状态下重复演出旧经过。

整理并入下一次真实状态更新的同一轮裁定，不为每次心跳另加一次整理模型请求，也不按字数硬截断世界状态。安静时不为缩短文本捏造外部变化；若角色和世界仍需承接的内容较多，应保留这些必要内容。事务日志与当前工作记忆承担不同职责。

普通任务在安全投影允许时，以 `worldDocument:{revision,paragraphs:[{id,text}]}` 提供同一份自然语言记忆，不要求重新建立实体、属性或关系数据库。段落 `id` 只在该文档版本内定位文字，不是世界实体、事件来源或可告诉角色的事实。更新格式为：

```json
{
  "worldPatch": {
    "revision": "照抄本轮 worldDocument.revision",
    "edits": [
      { "op": "replace", "id": "p2", "text": "店员把煮好的面端到桌边。" },
      { "op": "append", "text": "街角的书店今晚延长营业。" }
    ]
  },
  "perceptions": [{ "actorId": "bot", "text": "店员将面碗放在你面前，热气升起。" }],
  "outcome": { "status": "completed" }
}
```

示例中的版本和段落编号必须来自实际输入。`replace` 替换完整指定段落，`delete` 删除确已失效的指定段落，`append` 按顺序追加新段；所有地址均指向同一份原文，每个已有段落最多修改一次。未改部分保留原文，版本或地址错误时整份补丁不应用。`edits:[]` 表示不更新，也可以直接省略状态字段。程序先在内存中还原完整候选，再按原有提交边界验证并同笔保存状态、动作与感知，不会逐段公开半成品。

创世与虚构应用继续使用全文；尤其 `app_action` 要保留精确文件原文，不开放段落编辑绕过文件边界。普通任务如果时间或设备事实投影改变了世界正文，也会退回全文协议，避免把经过隐藏或更正的投影地址当成存档原文地址。超过200000字符补丁上限的旧状态也保留全文输入能力，仍可省略状态更新，或在一次合法全文更新中归并；不会在推理前直接失败。

增量更新减少未变文本的重复生成，不减少剧情必须表达的内容。世界记忆保存持续事实，角色状态保留自身客观处境，感知描写真正经历；简短状态栏只补必要信息，避免把一整段剧情在各字段重抄。必要的环境细节、NPC回应、行动后果和决定点仍须完整呈现。修复与增量协议的固定说明独立附加，覆盖自定义 World 文风提示的运行实例也能获得当前契约。

## 调度与提交

所有推理与提交仍通过同一串行队列。动作正在首次裁定、尚未持久化为 `ongoing`，或距到期不足 30 现实秒时，定时心跳让位；已经开始的长动作在其等待空档允许外部世界继续发展。

新的角色行动以及到期的结束裁定会取消尚未提交的定时心跳。取消只丢弃那份未发生的提案，不制造失败经历；迟到的模型结果不能写入状态。已经提交的世界变化不会撤回，后续动作从最新状态裁定。管理员主动发起的演化仍是有序写入屏障，不按后台心跳丢弃。

固定模式下，正常完成后的间隔仍使用 `tingleEveryUnits`，安静结果不改变这一成功节奏。自动模式下，连续 `quiet` 会逐步延长间隔，受配置上下限约束；安静结果如携带合法的 `nextIntervalTU`，取渐增间隔和建议中的较大值，再限制在配置范围内，因此建议可以延后检查，但不能加快静默轮询。有效提交采用合法建议，没有建议时恢复基准间隔。它只是下一次检查的调度建议，不是时间跳跃，不授权未来事件发生，也不要求角色等待；单独的建议不构成世界事务。让位于行动用 `yielded` 表示，不计为裁定失败。

一次心跳最多尝试3份提案，整个生成与纠正流程共享 `world.heartbeatTimeoutMs`（默认300000毫秒）的总时限，包含推理端点等待；超时会取消未提交提案，迟到结果不能落盘。

真实失败会累积连续失败次数并延长下次尝试间隔，达到上限后保持退避，避免按短间隔持续发起同样的失败请求。固定模式也对失败退避，但恢复成功后回到固定间隔。自动模式恢复成功后按有效结果安排后续检查。停止和重新启动使用不同调度代次，旧任务结束不能再启动旧计时链，也不会并行启动替代心跳。

## 运行状态与排查

一次 HTTP 请求完成仅表示收到模型响应，不代表世界裁定成功。心跳可能仍需解析、校验、纠正或写入；查看运行洞察时应同时检查 `world.task` 的 `tingle` 任务状态，而不能只根据 HTTP 200 或流式输出结束判断。

心跳记录区分 `committed`（通过校验并提交）、`quiet`（没有新变化）、`yielded`（让位于角色行动）和 `failed`（真实失败），并提供最近结果、错误、连续失败次数、当前间隔和下次检查时间。`quiet` 不生成剧情是正常结果；失败则保留具体错误，等待退避后的下一次尝试。原始调用记录仍用于核对模型实际返回的格式和内容，任务状态用于确认这些内容最终是否进入世界。

定向回归：`scripts/test-world-evolution.ts` 覆盖远方事件、合法外部身体影响、角色权限、事务来源、历史兼容及行动抢先；`scripts/test-world-evolution-normalization.ts` 覆盖投影静默、同文与省略状态的事件、来源引用及手机配对；`scripts/test-world-response.ts` 覆盖原生与单对象 JSON 适配和损坏响应拒绝；`scripts/test-world-proposal-schema.ts` 覆盖按任务收窄、原话阶段、补丁互斥和整字段修复协议；`scripts/test-world-task-prompts.ts` 覆盖任务隔离、固定前缀、自定义文本保留、可选剧情字段和精简预算。现有设备、时间、行动阶段、恢复及迁移测试继续覆盖相同提交边界。
