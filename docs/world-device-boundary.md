# 世界叙述与设备事实的边界

World LLM 不持有聊天平台的消息历史。它接收的行动意图，例如“拿起手机，查看某人的消息”，不是消息原文。如果把这种意图交给自由叙述，又把生成内容直接当作角色的感知，就可能将虚构消息写入世界状态，继而污染角色回复、记忆和关系。

收发消息继续走 Bot → 设备工具 → Koishi 的路径，无需等待 World 裁定，也不通过 World 转述消息正文。公开的 observe 已合并到 act，内部只读/历史观察仍保留。World 负责物理环境、身体行动和在场 NPC；真实平台消息、设备界面和收发结果由对应工具提供。此分工在虚构世界中也成立。

## 执行与提交

- Bot 和 World 入口都检查明确的设备意图。`act` 或内部观察中混入读取聊天、发送消息、操作软件等请求时，整个请求未执行，返回专用工具指引，不偷偷拆解或自动发送。普通拿放物品、面对面交谈、纸信阅读仍属于物理世界。手机持有状态以 `pick_up_phone`/`put_down_phone` 为准。
- World 的初始化、演化、行动、观察和到访离场共用提交检查。`worldState`、`actorStates`、`perceptions` 以及演化的 `externalChanges`、`actorEffects` 中出现明显的平台消息、通知或软件操作断言时，整份提案拒绝提交，最多给模型三次生成机会。失败不会把拟议内容交付为成功经历。
- 固定的事实归属规则追加在 World 系统提示中，覆盖可编辑提示词。用户提供的角色原话可以在当面发言中逐字出现，不因此被当作一次平台读取或发送。
- 虚构应用仅在内部应用请求中模拟软件。既有文件正文按原文处理，不把文件中讨论消息的文字误当聊天回执；普通世界更新不能借此改写文件。真实聊天平台始终由 Koishi 路径负责。

手机物理条件通过 `resolve_world` 的可选 `phoneState` 明确提交：`reachable` 表示无需新的物理行动即可触及，`location` 为已确立的位置或未知的 `null`，`usable` 表示硬件与供电可用，`perceptible` 表示真实通知动静能否传到角色。提交时四项须完整，省略则保留原值；不通过正文关键词猜测遗失或修复。只有获授权的常驻角色物理世界裁定可修改，访客、应用和跨世界任务不能越权写入，提交前还会复核权限。位置字段同样经过设备断言检查，不能夹带消息或软件结果。

这些条件与剧情、动作结果同笔写入权威日志，保存成功后才更新执行侧；不会在模型生成到一半时改变设备门控。失去可达性会解除持有，找回后仍需真正拿起。不可操作时取消尚未提交的手机任务，修复不会复活它们，已提交的平台发送保留实际回执。拿放工具继续负责持有状态与关闭应用，不替 World 编造放置地点。旧存档缺少该字段时兼容为可达、可用、可感知、位置未记录，不重写旧历史；后续剧情可以明确裁定不同状态。

`bot.unrestrictedPhone` 默认开启，为拿取操作增加一个明确的程序规则：手机不可达、损坏或无法感知时，`pick_up_phone` 可通过独立的 `phone_restore` 短事务恢复为可用、可感知且在手中。保存失败就不反馈成功；拿取不请求 World 模型，已有 World 草稿必须按恢复后的版本重新裁定，不能覆盖恢复事实。后续正常 World 更新会收到这项事实并向前衔接剧情，不重写旧记录、不编造先前完成过修理或寻找，也不替手机执行软件操作。穿越时恢复本实例所属的便携设备，不写远端剧情或访客状态。关闭此开关则不提供这种恢复能力，遵守上述物理条件。

旧世界把文件原文和场景一起存放，部分文件没有明确的结束标记。对这类格式，程序不能可靠区分文件正文与其后追加的文字，因此将不确定尾部保留为原始数据，不输入普通 World 裁定，也不把其中的内容重新认作场景事实。普通更新只生成物理情境部分，保存时由程序附回原尾部；对应虚构应用仍可读取原文。这是旧格式的保守兼容，不代表已经恢复了被混写的所有事实。

## 上下文与恢复

新交付的自然语言世界感知附带物理领域说明；平台通知、读消息结果和媒体保持各自来源。新工具尚未进入固定原生声明时，可按能力变化事件使用同名正文 JSON 调用，不能用 `act` 代替。固定声明和旧上下文只在正常压缩时刷新。

已学设备工具可由程序补齐真实界面导航，每一步留下实际调用与回执，`navigationFor` 标记它服务的目标工具；这不经过 World，也不把自然语言意图假装成发送成功。学过不等于当前有权限，缺少频道目标、工具失效或严格模式下的物理障碍仍会拒绝。默认模式可先执行真实的手机恢复拿取，再继续导航；缺少发送目标时不会先行恢复手机或打开应用。

升级时通过现有聊天指导事件追加来源澄清，不改写已发送给模型的历史前缀。世界状态和旧感知在再次交给 World 或恢复交付时，会过滤明确的设备断言；原始日志仍保留。被过滤的混合感知不沿用原始证据根，避免把包含虚构内容的整条记录重新认证为一次亲历。

成长整理和压缩同样要求按来源判断：存在有效事件编号，不表示原文支持任意结论；实际平台回执不能为另一个世界事件中虚构的聊天内容背书。

## 保证范围与已有污染

检查器针对明确措辞，是额外的程序防线，不能完整判断任意自然语言是否暗指一条真实聊天。来源规则和直接设备路径仍是架构基础；离线回归验证执行边界和具体事故模式，不保证模型永远不会在自由文本中产生幻觉。

升级不会删除旧摘要、成长认识和已计算的调节记录，也不会抹去实际已经发送的错误回复。已有污染若需彻底清理，应先归档，再逐项追溯原始事件及派生认识，追加更正；直接重置世界会丢失现有生活进度，不能作为无提示的自动迁移。仅清理聊天消息列表也不能清除世界、记忆和成长中的错误断言。

行动机会与事实分开：World 只提出物理世界建议，不能借选项编造未读消息、邀请或设备操作结果。程序依据已交付的通知/聊天元数据和可用能力补充设备机会，角色的成长作为选择线索；选择及真实回执以前，候选不能进入成长证据。
