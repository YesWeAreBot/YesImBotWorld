# 聊天因果、暂停与成长依据修复

这次问题不是只有措辞不一致：聊天排序、程序休息回执、跨频道成长召回、旧认识和压缩降级叠加，使角色收到了彼此矛盾的事实。

## 消息顺序

入站平台时间与本机发送确认时间分属不同的时钟。它们保留原值和来源用于展示，不再承担共同排序的职责。新消息在接收入口或发送确认时领取本机顺序，领取发生在查昵称、处理图片等异步工作之前。同一频道的入站处理串行交付，历史补拉按已知消息编号和平台序号锚定，缺乏锚点时明确标注先后未知。

旧数据只追加排序和来源字段，不伪造接收时间。旧混合时钟显示次序不能当作已确认的因果关系；Bot 通过追加说明获知这个限制，已有上下文不重排。来源与引入提交见 [消息排序历史](message-ordering-history.md)。

## 暂停与设备通知

- `rest`、`wait` 的到期、中断和取消只回报实际计时，不生成睡着、醒来或体力恢复的身体事实。
- 自主 `rest` 与 `wait` 共用原有暂停时间预算，包括提前中断和取消前已耗费的时间。超额时明确说明占比和选择；确有需要可对同一工具紧接着确认一次。真人接管不受自主策略预算限制。
- 匿名通知、旧消息回读和记忆压缩不再清空重复行为计数；真正的新消息、已完成自主动作或新的世界事实才算进展。
- `put_down_phone` 仍关闭当前应用关注，允许的通知仍会震动。改免打扰必须拿起手机、打开聊天应用并进入频道。
- 免打扰控制提醒与唤醒，不删除聊天消息。正在阅读的频道仍可更新可见内容，但免打扰消息不主动打断暂停。通知设置落盘失败不返回成功。

## 成长依据

程序在实际交付处提供频道、发送者稳定身份和消息归属；这些元数据不允许模型自行声明。逐消息片段保留原消息的文本、图片位置和来源。聊天关系要求该对象真实发出的非本人消息，混合快照中的姓名列表不能证明某句话由谁说出。

通知或频道列表不证明人物正在关注某个私聊；注意状态只能从实际打开或查看的频道形成。匿名震动不触发按聊天对象召回，频道状态不跨频道套用。

习惯和性格需要共同的真实行为依据与跨日实践，不能拿无关动作凑次数，也不能每次重复就新建一份近义习惯。关系、承诺、偏好和当前状态仍可及时更新，无须等待多日。

旧版缺乏可信范围或行为依据的认识保留供审查，停止自动召回和进入固定成长摘要，并通过有界、持久化的通知队列追加“待复核”说明。隔离不表示旧认识全部错误；明确纠错另有追加记录，不删除原始证据。压缩和重启不会丢掉未交付的说明。

## 压缩完整性

压缩必须返回完整、唯一、非空的两个约定标签。格式失败只修正一次，再失败则保留整个原上下文；不能再把输出前 4000 字当作成功摘要。多段压缩中途失败也不提交部分结果。

旧版程序写入的休息中断“睡醒”句子，只在送给压缩器的只读投影中标为无效身体证据。原始事件与当前 Bot 固定前缀保持不变；真实聊天或世界观测中关于睡眠的叙述不会因此被抹去。

## 验证与部署

回归使用隔离数据库、临时世界目录和假模型回执，覆盖混合时钟、异步入库、历史补拉、重启迁移、通知隐私、暂停预算、证据归属、隔离队列及压缩失败。测试不向聊天平台发送消息，也不修改运行实例的数据。

重新加载构建后的插件后，新记录使用新的顺序与依据。旧记录的来源补全及成长隔离在正常加载路径执行，保留原始时间、消息和证据；无需重置世界。行为质量仍需在新实例实际对话中复核，程序校验不等于已经证明模型此后不会误解对话。
