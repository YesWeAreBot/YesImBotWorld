# 世界裁定成本与交互调度

普通短 `act` 只需要一次 World 请求。受理记录、校验、保存和回执都是本地操作。真实持续过程可先提交 `ongoing`，到世界时钟的预计结束时刻再结算；短动作不会为了填满估计时长被强制拆成两次。不同调用的相同意图仍是不同尝试，不能重用旧的已完成结果。

## 请求和结果

系统提示采用稳定公共前缀和当前任务规则，规则不会每轮随机变化。动态输入只保留一份 `action`：意图、目标、原话和起止时间；`pendingActions` 只列其他待结算动作，不把请求指纹、重复的当前动作或重复时钟字段送给模型。其他待结算动作不能被当前任务推进或完成。

权威时间在 `timeAuthority`，旧状态时刻在 `stateAsOf`，二者不能混用。手机物理条件通过 `phoneAuthority.actorId` 明确所属角色。自然语言世界记忆仍完整提供，秘密留在世界侧；未为了缩短输入截掉角色可能需要承接的事实。补丁协议、局部修复及权限详见 [世界心跳与角色行动边界](world-evolution.md)。

身体行动另带最近三次同一角色的已结算请求与结果依据，总量限制在 3600 字符。结果只取该行动同笔提交、交付给该角色的感知，保留事件引用；不混入别人的私密感知、未选建议或待结算行动。当前感知已经包含的正文只引用，超限内容整项标记省略，不截断成不同含义。执行状态与内部诊断并不证明意图成功，World 仍需对照实际结果：普通行动应有实际进展或明确阻碍，不能用“已经尝试”冒充完成，也不能因反复失败而凭空加重伤势。这里增加的是有来源的裁定依据和提示约束，没有新增模型评价请求，也没有用关键词检测冒充对自由剧情的完整语义验证。

意识采用可选的明确事实 `consciousness`：`awake`、`asleep`、`unconscious`。旧记录缺失时保持未知，允许思考，不从睡觉修辞、`rest/wait` 或手机状态补写。创世和实际身体行动可更新；观察、应用操作无权改变。真实睡眠通常作为持续行动开始，到实际时钟的结算点判断是否醒来；明确睡眠或昏迷期间暂停自主生成。没有待结算睡眠行动时，已确立睡眠随真实时间自然结束也可由世界心跳记录为生理原因，按原有来源引用机制提交 `awake`；昏迷恢复需要已确立条件或真实外因，不能任意倒计时解除。这是意识与调度边界，不是完整的睡眠生理模拟。

剧情正文描述实际经历，状态只记录需要保留的变化，状态栏与建议均可省略。错误的可选建议按整项移除，不触发一次新的世界裁定；全被移除时显式保存 `[]`，避免继续显示旧菜单。正文、状态栏、世界状态、角色状态、手机事实和演化来源仍完整验证，不能用建议过滤绕过事实校验。应用回执没有剧情建议权限，不经过这项过滤。

裁定默认通过 OpenAI 兼容的 `response_format: json_schema` 返回一个 JSON 对象，不声明或调用 `resolve_world`。请求包含当前任务的字段合同，并限定可接收感知的角色；一个角色最多一份感知。`world.responseFormat=json_object` 适用于只支持 JSON 对象的服务，`tool` 显式保留原生工具兼容路径。两种兼容模式也执行全部语义校验，服务拒绝 Schema 时不会自动降级或重发。该接口的服务支持见 [vLLM Structured Outputs](https://docs.vllm.ai/en/stable/features/structured_outputs/)。

下发给解码器的是原始裁定契约的独立生成副本：不包含当前 vLLM 无法可靠执行的 `uniqueItems` 和 `not`，重复、互斥及事实权限仍由程序在提交前校验。局部修正使用两个各自完整的对象分支（完整裁定或仅 `repair`），每个分支独立声明字段、类型、必填项及禁止未知字段，避免解析器忽略“根对象字段 + 部分 oneOf 分支”的约束。原始工具契约不改写，也不会因后端拒绝而自动退回无约束生成。兼容验证须覆盖初始化、演化以及两者的纠错请求，不能只验证首轮初始化或语法编译成功。

`world.proposalMaxTokens` 默认 2048，每次裁定取它与 `world.maxTokens` 的较小值，避免维护/外观生成的较大预算被用于反复裁定。`world.actionTimeoutMs` 默认 180000，覆盖一个行动的排队、生成、纠错及最终结算；已确认 `ongoing` 后等待世界时钟的真实过程不消耗这个预算。超时后未确认的部分记录为失败，已提交的开始经过保留，迟到输出不得提交；失败状态也遵守串行提交顺序，不能使无关行动发生版本冲突。单次维护请求同样有总时限。

LLM 客户端识别 `finish_reason=length`、过滤、中断和损坏的 SSE 帧。即使截断前恰好已经出现一个可解析 JSON，也不能将整次响应当成有效完成。调用详情保留原始请求、返回、用量、结束原因与明确错误，失败不会伪装为已完成。

服务端即使以 HTTP 200 打开流，也可能在后续返回 `error`。错误正文为空时，客户端仍显示上游 `type` 和 `code`，并说明具体原因须查看模型服务日志；不会将空正文猜测成显存不足或模型能力问题。

成长整理默认也使用 JSON Schema（`bot.growth.responseFormat`），兼容模式为 `json_object` 或 `text`。请求内的身份使用 `s1…` 短引用，只修改结构字段，正文和证据原文不变；程序按本次实际展示的白名单还原身份，未知编号拒绝。字段类型、缺字段、身份错误与引文不匹配分别报告。`maxInputChars` 约束消息正文预算；服务处理 `response_format` 中的 Schema 时可能另有上下文开销。

## 等待世界时处理聊天

`bot.strictToolLoop` 保持默认开启。新增 `bot.interruptibleWorldActions` 默认开启：等待自主 `act` 的结果时，实际收到允许唤醒的新聊天事件，可进行独立设备操作以及思考、查询帮助、回忆、等待和取消。不提前提交依赖该行动结果的后续身体动作、世界观察或跨世界旅行。

该窗口由真实新聊天开启，每次最多八个自主决定；设备操作仍等真实回执。失败、重复回读、内心独白和帮助回执不能持续延长窗口，没有进展便继续等待世界结果。新聊天可以再次开启窗口。耗尽额度不代表聊天完成，不清空未读，也不生成虚假的失败回执。能力变化只在待完成行动边界追加进上下文；每次通知和额度变化不反复改工具列表。原固定上下文只在正常压缩时刷新。

静默通知、旧消息重放、自己的发送回声和恢复的旧回执不会开启窗口。`wait` 与无需压缩的 `rest` 保留计时及事件打断语义；人工接管、停止和设备物理可用性仍有优先权。关闭 `interruptibleWorldActions` 恢复完整等待；关闭 `strictToolLoop` 则继续使用原来的 `blockingAct`、`sendBlocking` 并发设置。

World 生成期间可以实际拿放手机。若持有状态变化，包括拿起后又放下回到原姿态，原裁定输入视为过期：只追加最新执行事实与时钟，弃用未提交草稿，重新裁定完整结果，仍共享最多三次请求的预算。不能只删掉 `phoneState` 却留下矛盾剧情。短暂的本地锁只覆盖拿放状态修改和世界日志提交、发布，不覆盖 LLM 生成；提交前再次验证版本，防止迟到剧情覆盖已完成的设备动作。

## 模型端点与维护

`serializeSameEndpoint=true` 仍保证每个同源模型端点只执行一次请求。维护任务保留自己的串行文件提交和分段依赖，但在每次模型请求后释放端点。成长整理、压缩、外观生成与世界心跳使用后台队列，实时请求优先；两类均有等待时最多连续执行三个实时请求，随后给最早的后台请求一次机会，避免长期饿死。

程序调度可以同时等待世界、接收聊天，不代表后端支持同时推理。共用同源端点且开启互斥时，Bot 仍需等待正在执行的 World 请求。确认后端支持并发后可关闭 `serializeSameEndpoint`，或使用不同端点。程序不会为提速擅自关闭互斥。

取消会及时结束调用方等待，排队请求不再开始。已开始的底层请求若异常地忽略取消，端点要等其返回或超时后才交给后续推理，避免在旧请求仍运行时叠加新请求；行政停止、重置及迟到结果的权限隔离不会因此失效。

导航和参数前置拒绝也计入防重复守卫，每个尝试只计一次。`breakLoop=false` 保留不自动禁用工具的语义，但连续拒绝仍有最长 60 秒的指数退避；连续失败期间只允许一次真实新感知提前唤醒，消息洪流不能不断清零截止。已成功执行的工具才结束失败段，补全导航步骤不冒充目标成功。

上下文整理失败保留原始经历与固定前缀，快照、生成和保存失败统一按 30、60、120、240、300 秒退避。未超工作窗口/附件预算时可继续生成，超预算时暂停生成并继续保存新事件；`rest`、新通知和反复接管不能绕过保护。技术维护不会写入角色睡眠、疲惫或失神。成功整理后才切换固定块与工具声明；总览会显示整理/待重试状态。

若固定提示词本身已经达到 `bot.maxWindowChars`，整理动态经历不能解决超限：系统显示配置阻塞，停止新的自主推理与无收益的压缩，继续接收和保存事件。增大工作窗口预算后重新检查；不会自动删减作者设定、改写缓存前缀或把维护描述为角色睡眠。这里的字符预算是工作窗口估计，不能替代模型服务的 token 限制。

## 耗时记录

运行洞察的 `world.tool` 中，每次裁定阶段有一条“世界裁定 · 耗时”（或失败、取消）记录，带 `id`、`source`、角色、行动阶段及 `timing`。毫秒都是现实经过时间，不是世界 TU：

| 字段 | 含义 |
| --- | --- |
| `queueMs` | 世界有序队列与模型端点等待的总和 |
| `worldQueueMs` / `endpointQueueMs` | 上述两类排队的分项，不能再与 `queueMs` 相加 |
| `preparationMs` | 读取裁定输入、投影与组装请求 |
| `modelMs` | 首次模型请求执行，包含网络与服务端处理 |
| `validationMs` | 首次响应的本地解析及校验 |
| `repairMs` | 后续纠正请求及其校验，排队仍计入 `queueMs` |
| `saveMs` | 本地提交，包括开始阶段的受理保存 |
| `totalMs` | 本阶段总体经过时间，包含排队，不含长动作两阶段之间主动等待世界时钟的时间 |
| `attempts` / `repairs` | 模型请求次数及其中额外的纠正或执行输入刷新次数 |
| `inputChars` / `outputChars` | 初始消息与累计模型结果的序列化字符数，非 tokenizer token 数 |
| `discardedSuggestions` | 处理过程中移除的非法建议项数量 |
| `executionRefreshes` | 因拿放等独立操作使输入过期而重新裁定的次数，与模型提案出错区分 |

分桶可能因小额调度开销、记录和四舍五入与总时长略有差异。尚未进入裁定就在世界队列内取消的请求另有“排队取消”记录，其模型及纠错耗时为零。关闭的记录不接受迟到推理回调修改。

优先根据排队占比、纠错率、首轮输出量与整体延迟判断后续优化。没有实际瓶颈证据时，不进一步拆分角色状态、丢弃世界事实或改造持久化格式。
