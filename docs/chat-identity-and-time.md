# 聊天身份与世界时间的事实来源

聊天署名、账号归属和行动归属是三种不同的信息。

- 消息署名保存平台在收取或补拉该消息时提供的群名片/昵称。工具发送时查询本频道身份；拿不到群名片就明确区分账号昵称与未知。历史署名不随当前名片变化重写。
- 当前频道额外说明人物使用的平台、账号和可确认的群名片。消息归属按平台与账号判断，不能仅靠角色姓名、昵称或旧 `self` 标记判断；同一人物的另一连接账号也要区分出来。
- 新消息保留当时是否已确认为角色连接账号的记录。账号后来移除，不把旧消息变成别人的话；后来新增账号，也不把更早未知归属的消息追溯为自己的发言。未登记与未知都不证明一定属于别人。
- 账号发出一条消息，不证明人物亲自或自愿发送。实际工具发送、外部账号消息、历史补拉分别保留已知来源；手动操纵与认领仍由原有控制经历决定。`externalSelfMessages=simulate` 的认领玩法保留，身份说明只进入回执，不进入真正发送的正文。

旧记录使用“（我）”“本账号”等占位名且没有原始昵称时，呈现为“昵称未记录”，同时保留可确认的账号归属。不能用今天的群名片伪造历史署名。

账号连接情况在 Bot 生成边界检查，变化只追加一条系统身份事件；不会重建已有系统前缀或修改旧消息。压缩时更新固定块。压缩和成长整理是独立请求，都会显式收到账号映射，不能假定它们看过 Bot 的系统提示词。

表情包的会话用途也是每次消息的事实。平台明确上报的表情类型会与媒体一起保留，普通图片不会因为文件名、GIF 格式或相同素材过去曾作为表情出现而改成表情。NapCat 的商城表情可以通过协议专用 `file=marketface` 上报；这是[平台消息格式](https://napneko.github.io/develop/msg)提供的标记，不是对普通文件名进行语义猜测。

会话标签显示本条是否另附文字、表情/其他媒体的数量、实际 @ 和引用指向；引用或转发内部的元素不改变外层消息的指向与计数。表情与文字共同参与表达，图案只提供可能的表达线索，不能直接断言发送者心情、谈论主题、是否已读或是否希望被回复。数量未知的旧记录不补猜数字，已保存的历史请求也不改写。

可见通知和记录回读共用聊天记录编号与平台消息来源。不同消息编号连发同一表情是多个真实发言，回读同一消息仍是同一证据；同一 `media:N` 只证明素材相同。外部插件或其他客户端用本账号发送的表情同样保留这些线索，模拟认领时会话说明仅在回执中，不能混入真正的发送正文。

引用在实时消息、发送存档、频道回读、云端补拉和合并转发中统一表示为 Koishi `<quote id="原消息ID"/>`，可带经过转义的 `name`、`text` 预览属性。预览描述被引用消息，不是当前发言者的新正文，也不会附带下载或发送其中的媒体。平台未提供引用 ID 时保留无 ID 的标签，不猜造可回复的目标。

发送可使用 `reply_to`，也可在 `msg` 中照抄带 ID 的 `<quote>`。两条路径指向同一消息时只发送一个真实引用，并去掉正文标签及其后空白；多个不同目标或无效标签会在发送前报错。预览属性不进入发送正文或平台引用属性，去重和长度校验使用规范化后的正文；原始工具调用仍原样记录。引用与文字、图片和表情包的原有发送顺序保留。

旧存档的 `[引用 msg:ID]` 和 `[引用了一条消息]` 只在已有引用元数据佐证时，在读取展示中转换为 `<quote>`。真正作为普通文字发出的标记、与元数据冲突的 ID、既有上下文和原始数据库内容不改写。更新后的来源说明通过追加事件进入已有上下文，不重写缓存前缀。

世界当前时间由 `WorldClock` 决定。每次 World 裁定都会收到同一次采样的 TU、完整日期/时刻、历法来源、时区、UTC 偏移，以及旧状态的记录时刻和已流逝世界秒数。现实同步使用服务器时钟；独立时间线使用配置与已保存历法。世界是否为现实场景不决定时间同步。

明确的公历初始时刻不能被模型随意替换。自定义纪年无法建立时应停止创世并解释错误，不能偷偷回退到默认年份。

World 输出中的明确“当前日期/年份/星期”断言会按本次请求时钟核验，冲突进入有上限的修复流程，不能直接保存。历史日期、原话、文件内容、假设和计划不作为当前时间校验。旧状态中冲突的当前时间断言只在读取给模型的投影中隔离，不改写历史档案。

这些校验不等于通用事实核查。模糊的自然语言时段、角色对时间的误解及其他世界知识不能仅靠日期匹配判定真伪。程序保证时间资料有明确来源；模型负责在这个边界内叙述世界，并区分引擎知道的时间和角色实际能感知的时间。
